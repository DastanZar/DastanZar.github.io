04 / METHOD

Method, not magic.

The same contract in every repo, so the numbers can be compared instead of admired.

“A benchmark is an argument. A receipt is evidence.”
01

Measure on the machine you have.

CPU timings, interpreter parity, real model weights. No invented H100 numbers; GPU projections are labeled models with the assumptions attached.

02

Make the claim runnable.

A CLI, a test, or a live app: a path to the number that a stranger can execute. If a claim cannot be reproduced from the repo, it does not count.

03

Let CI defend the claim.

Tests assert the metric. Receipts are committed. The site reads them; it never retypes them. Drift fails the build.

I'm Abhinav Chauhan. I work on the unglamorous layer between a model and its bill.

Caches, kernels, schedulers, and decoding loops. I like small, complete projects with sharp claims and honest measurements — the kind of work that survives a p99, a tight GPU budget, and a reviewer who asks where the number came from.

Twenty public repos; ten deep case files and a 20-card index on this page. Each case file is built around one inference problem and one committed receipt. The index keeps the rest of the inventory inspectable by layer, not by chronology.
